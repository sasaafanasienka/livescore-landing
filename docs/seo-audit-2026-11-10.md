## 3. Что сходится (хорошие новости по вашему главному вопросу)

Вы боялись, что сайтмапы и JSON-LD разъехались с контентом. По сайтмапам — **расхождений нет**:

| Проверка | Результат |
|----------|-----------|
| URL в `MARKETING_SITEMAP` ↔ реальные маршруты | 8×6 = 48, все отдают **200**, лишних/битых в сайтмапе нет |
| `canonical` = фактический URL | **48/48** совпадают, абсолютные, без трейлинг-слеша |
| `hreflang` | **48/48** — по 6 локалей + `x-default` → `/en`, взаимные |
| Самоописывающие `<html lang>` / `dir` | корректно, `ar` = `rtl` |
| `/` → локаль | 307 по `Accept-Language`, без заголовка → `/en` |
| `/de`, `/en/guide` | 404 (не soft-404) |
| `/en/pricing/` | 308 → `/en/pricing` |
| `robots.txt` → sitemap index | есть, абсолютный URL |
| Уникальность title/description | 48/48 уникальных, дублей нет |
| JSON-LD `FAQPage` ↔ видимый текст | совпадает во всех локалях, **кроме `fr`** (см. 4.7) |
| Изображения | у всех заданы `width`/`height`/`alt` (нет CLS-риска), webp/optimized |

То есть проблема не в том, что сайтмап «устарел» — он полный и правильный. Проблема в том, что **на эти 48 URL ведёт ноль внутренних ссылок**, а метаданные и наполнение деградировали.

## 4. Критические находки

### 4.1. P0 — OG/Twitter-картинки отдают 404

`src/lib/seo-metadata.ts:62` и `src/app/[locale]/layout.tsx:34,45` ссылаются на `/images/og-image.jpg` и `/images/twitter-image.jpg`. В `public/images/` этих файлов **нет** (там только `logo.png`, `hero-*.webp`, `home-*.webp`, `mockup-*`, `testimonial-*`).

```
/images/og-image.jpg      -> 404
/images/twitter-image.jpg -> 404
```

Следствие: пустые превью при шеринге в Telegram, X, LinkedIn, WhatsApp, Slack; нет изображения в Discover. Для продукта, который живёт в Telegram, это прямое попадание по каналу привлечения. При этом требования из `_bmad-output/.../content-and-seo-surface.md` («Meta + Open Graph + Twitter — per page, per locale») формально считаются закрытыми.

**Фикс:** положить `public/images/og-image.jpg` (1200×630) и `twitter-image.jpg` (1200×600) либо генерировать их через `app/[locale]/opengraph-image.tsx` (`next/og`) — второй вариант лучше: даёт разные карточки для 48 страниц автоматически.

### 4.2. P0 — на 42 из 48 страниц нет `<h1>`

`<h1>` есть только на главных (`HomeHero.tsx:39`). Все страницы, которые рендерит `MarketingMarkdownPage.tsx`, выводят тело как **один `<p>`**:

```tsx
// src/components/MarketingMarkdownPage.tsx:43-45
<p className="max-w-xl whitespace-pre-wrap text-lg text-foreground-accent">
  {body}
</p>
```

То есть заголовков нет вообще: ни `<h1>`, ни `<h2>` для разделов. Разметка страницы `/en/faq` — это заголовок и один абзац со всем текстом, включая вопросы FAQ. Для справки: у `/en/official-channels` единственный `<h2>` — «League channels» из списка каналов, а сам текст страницы идёт абзацем **до** него.

Следствие: краулер не понимает тему страницы; нет шансов на сниппеты по «how to add a football bot to a Telegram group» и подобным запросам; вопрос/ответ в FAQ не распознаются как структура (хотя `FAQPage`-схема их заявляет).

**Фикс:** заменить `whitespace-pre-wrap`-абзац на минимальный рендер markdown-блоков: первый блок → `<h1>`, остальные абзацы → `<p>`, строки-вопросы в FAQ → `<h2>`. Правка локальная, в одном компоненте + `src/lib/content.ts`.

### 4.3. P0 — ноль внутренних ссылок на 8 разделов: 42 страницы — сироты

Все внутренние ссылки сайта ведут на якоря главной:

```ts
// src/data/menuItems.ts
{ text: "features",   hash: "features" },
{ text: "forGroups",  hash: "how-it-works", query: { how: "groups" } },
{ text: "forChannels",hash: "how-it-works", query: { how: "channels" } },
{ text: "faq",        hash: "faq" },
```

`Header.tsx` и `Footer.tsx` строят ссылки только из этого массива → на `/pricing`, `/faq`, `/guide/*`, `/official-channels`, `/privacy`, `/terms` **не ссылается ни одна страница сайта** (проверено на всех 48: `pages_linking_to_subpages = 0`). В футере нет даже Privacy/Terms — для юридических страниц это ещё и формальная претензия (Google Ads, App Store, Telegram-требования).

Отдельно показательно: в контенте главной **уже есть тексты для этих ссылок, но они не используются**:

```json
"pricing":  { "moreLink": "Full pricing page" },
"channels": { "seeAll":   "See all league channels" },
"faq":      { "moreLink": "Full FAQ" }
```

`src/lib/home-copy.ts:53,61,66` объявляет поля `moreLink`/`seeAll`, но ни один компонент их не рендерит — то есть после правки контента ссылки «потерялись». Более того, контракт это **запрещает** для одного случая:

```ts
// scripts/contracts/home-landing.contract.ts:154-158
assert.doesNotMatch(landing, /href=["']\/official-channels["']/,
  "home must not link to the standalone official-channels page");
```

**Фикс:** (а) футер — постоянный блок ссылок на 6 содержательных страниц + Privacy/Terms; (б) меню — «Pricing» и «FAQ» как реальные страницы; (в) на главной отрисовать `moreLink`/`seeAll`; (г) пересмотреть решение контракта про `/official-channels` — сейчас это гарантированный сирота, который при этом лежит в сайтмапе; (д) на подстраницах — блок «смотрите также» (guide/groups ↔ guide/channels ↔ pricing).

### 4.4. P0 — 12 индексируемых страниц с текстом-заглушкой `TODO`

`content/*/privacy.md` и `content/*/terms.md` (6 локалей × 2) начинаются с `TODO` и содержат «This Privacy page is a placeholder». При этом они:

- в сайтмапе (`src/lib/seo-sitemap.ts` → `MARKETING_SITEMAP`);
- без `noindex`;
- в `<title>`/description после деривации из тела:
  - `/en/privacy` → **`Live Score — This Privacy page is a placeholder.`**
  - `/en/terms` → **`Live Score — This Terms page is a placeholder.`**

Двенадцать таких страниц на новом домене — прямой сигнал «низкая ценность» и риск для всего хоста.

**Фикс (быстрый):** `noindex, follow` + исключить из сайтмапа, пока нет реального текста.
**Фикс (правильный):** написать оператора, контакты, что собирается (данные Telegram, Stars), юридическое лицо, применимое право — это ещё и E-E-A-T.

### 4.5. P0 — почти половина контента главной не попадает в HTML

Главная содержит 730 слов копирайта (`content/home/en.json`), в HTML — **392** (~54%). Не видны краулеру:

- **все 8 ответов FAQ** — `FaqAccordion.tsx:36-56`, Headless UI `Disclosure` не рендерит закрытую панель;
- **2 из 3 табов** «How it works» (groups, channels) — `HowItWorksTabs.tsx:57-78`, рендерится только активный `TabPanel`.

В HTML остаются только вопросы и лейблы табов:

```
"What is Live Score?"                 → есть
"A Telegram football app. The bot..." → нет (ответ FAQ)
"Send /group to the bot..."           → нет (таб Groups)
```

Следствие: самая ценная часть главной (инструкции «как подключить группу/канал» — это ровно то, по чему ищут) отсутствует в DOM; проверка «контент в схеме = контент на странице» для главной становится невозможной.

**Фикс:** рендерить панели всегда (скрывать через `hidden`/CSS, а не unmount) — например `static`-проп у Headless UI `DisclosurePanel`/`TabPanel` + `hidden`-класс. Альтернатива: продублировать FAQ-контент статическим блоком ниже.

### 4.7. P1 — JSON-LD: есть, но неполный и не покрывает 36 страниц

Сейчас схемы на 12 страницах из 48: `Organization` + `SoftwareApplication` на 6 главных, `FAQPage` на 6 `/faq`.

| Объект | Что есть | Чего не хватает для rich results / entity |
|--------|----------|-------------------------------------------|
| `Organization` | `name`, `url`, `sameAs` | `logo` (Google требует для knowledge panel), `description`, `sameAs` ведёт на deep-link `t.me/LiveScoreAppBot/app` вместо профиля `t.me/LiveScoreAppBot`, нет `contactPoint` |
| `SoftwareApplication` | `name`, `applicationCategory`, `operatingSystem`, `url`, `description` | нет `offers` / `aggregateRating` / `review` — **без любого из них Google не показывает rich result для приложения**; нет `featureList` |
| `FAQPage` | 3 Q&A с `/faq` | работает, но 3 вопроса — это минимум; ответы FAQ главной (8 шт.) без схемы |
| `BreadcrumbList` | нет | нужен на 42 подстраницах для хлебных крошек в SERP |
| `WebSite` / `inLanguage` | нет | полезно для entity и мультиязычности |

Ещё три вещи:

1. **Дублирование FAQ**: на главной 8 вопросов (`content/home/*.json`), на `/faq` — 3 (`content/*/faq.md`), причём они пересекаются («What is Live Score?», «Who is it for?», «What about Chat Premium?» vs «What is Chat Premium?»). Два URL конкурируют за одни запросы — каннибализация. Нужен один «канонический» FAQ, второй — сокращённый тизер со ссылкой.
2. **Типографика расходится со схемой во `fr`**: тело страницы проходит через `typograf` (`MarketingMarkdownPage.tsx:37`), а JSON-LD строится из сырого markdown (`seo-jsonld.ts:46`). На `/fr/faq` в схеме `"Qu’est-ce que Live Score ?"` (пробел перед `?`), а на странице — `"…Live Score?"`. В `en/ru/es/pt/ar` после нормализации совпадает. Формально не критично, но это ровно тот класс расхождений, которого вы опасались; лечится одной строкой — прогнать текст схемы через тот же `typografText`.
3. `SoftwareApplication.description` («Live football scores and match updates through LiveScoreAppBot on Telegram.») не встречается на странице — расхождение описания продукта на сайте и в разметке.

### 4.8. P1 — сайтмап без `lastmod`, главная и `/official-channels` без кэша

**Сайтмап** (`src/lib/seo-sitemap.ts:43-65`) отдаёт `<url><loc>` и ничего больше:

```xml
<url><loc>https://football-live-bot.online/en/pricing</loc></url>
```

Нет `lastmod` (а он у вас как раз критичен — контент правится активно), нет `xhtml:link`-альтернатив, нет `priority`/`changefreq` (не обязательны, но `lastmod` реально экономит краулинговый бюджет и ускоряет переобход).

**Кэш** — замер на локальной production-сборке:

| URL | TTFB (avg) | Cache-Control |
|-----|-----------|----------------|
| `/en` | 165 ms | `private, no-cache, no-store, max-age=0, must-revalidate` |
| `/en/official-channels` | 129 ms | `private, no-cache, no-store…` |
| `/en/faq` | 30 ms | `s-maxage=31536000, stale-while-revalidate` (CDN HIT) |
| `/en/pricing` | 29 ms | то же |

`export const dynamic = "force-dynamic"` (`src/app/[locale]/page.tsx:27`, `official-channels/page.tsx:24`) отключает и SSG, и CDN. Ради свежести списка каналов (обновляется раз в 300 c через fetch-кэш) вы платите полной динамикой на самом важном URL. Разница ~5× по TTFB, и на Vercel это ещё и стоимость.

**Фикс:** для главной — `export const revalidate = 300` (ISR) вместо `force-dynamic`; список каналов останется свежим за счёт `next: { revalidate }` в `official-channels.ts:241`. Для `/official-channels` можно оставить динамику, но лучше тоже ISR + тег `official-channels` для on-demand revalidation.

### 4.10. P2 — `llms.txt` / `llms-full.txt` описывают прошлую версию сайта

```
public/llms.txt:12        → "Marketing page for app-owner league channels (static until live list wiring)"
public/llms-full.txt:32   → "official-channels is indexable even when live channel data is not yet wired on the public site"
```

Но список **уже живой**: `/en/official-channels` отдаёт `data-mode="live"` и 12 каналов (`champions_league_live_feed`, `premierliga_live_feed`, …). Это самое заметное расхождение «контент ↔ SEO-артефакт» — и оно в llms-файлах, а не в сайтмапе: сайтмап описывает сайт корректно, а вот текстовое описание сайта для LLM-агентов отстало от продукта.

**Фикс:** обновить оба файла, убрать «static/not yet wired», добавить, что список живой и обновляется автоматически. Заодно: `llms.txt` перечисляет только англоязычные страницы + главные остальных локалей; логичнее дать полный список 48 URL (он уже есть в `llms-full.txt`) и явно указать `x-default`.

### 4.11. P2 — тонкий и почти дублирующийся контент на 42 страницах

| Тип страницы | Слов (диапазон по локалям) |
|--------------|---------------------------|
| Главная | 333–407 |
| `guide/groups` | 86–123 |
| `guide/channels` | 86–114 |
| `official-channels` | 99–126 |
| `faq` | 90–110 |
| `pricing` | 51–58 |
| `privacy` / `terms` | 29–41 |

`guide/groups` и `guide/channels` — это один и тот же текст с подстановкой `group → channel` (8 замен, проверено построчным диффом), т.е. при 6 локалях это 12 почти идентичных URL. Вкупе с 6 локалями тонких страниц это выглядит как doorway-паттерн для нового домена.

**Рекомендация:** либо расширить каждый гид до 350–500 слов (пошагово, скриншоты, типы уведомлений, ошибки регистрации, «как отписаться», «как сменить язык»), либо на старте оставить индексируемыми `en` + `ru`, а остальные локали закрыть `noindex` до наполнения. Второй вариант честнее для нового домена и снижает риск «thin content» фильтра.
