## 3. Что осталось нетронутым (P0)

### 3.1. OG/Twitter-картинки по-прежнему 404

```
/images/og-image.jpg      -> 404
/images/twitter-image.jpg -> 404
```

Все 6 страниц ссылаются на несуществующие файлы (`seo-metadata.ts:62`, `[locale]/layout.tsx:34,45`). Теперь это единственная карточка сайта — и она битая. Для Telegram-продукта это самый дешёвый и самый заметный фикс.

### 3.2. 46% текста главной всё ещё не в HTML

`/en`: 730 слов в `content/home/en.json` → **392** в HTML.

- 8 ответов FAQ не рендерятся до клика (`FaqAccordion.tsx`, Headless UI `Disclosure`);
- 2 из 3 панелей «How it works» не рендерятся (`HowItWorksTabs.tsx`, только активный `TabPanel`).

Теперь это критичнее, чем в round 1: главная — **единственная** индексируемая страница. Из неё краулером вырезаны ровно те блоки, которые закрывают запросы «как подключить бота в группу/канал» и «часто задаваемые вопросы».

### 3.3. JSON-LD неполный, а `FAQPage` теперь нет вообще

На всех 6 страницах — только:

```json
{"@type":"Organization","name":"Football. LIVE","url":"…","sameAs":["https://t.me/LiveScoreAppBot/app"]}
{"@type":"SoftwareApplication","name":"Football. LIVE","applicationCategory":"SportsApplication", …}
```

- `FAQPage` пропала: страница `/faq` удалена, `faqPageJsonLd()` в `seo-jsonld.ts:46` осталась, но **нигде не импортируется** (мёртвый код). При этом на главной видимы 8 вопросов FAQ.
- у `Organization` нет `logo` и `description`, `sameAs` ведёт на deep-link `/app` вместо профиля `t.me/LiveScoreAppBot`;
- у `SoftwareApplication` нет `offers`/`aggregateRating`/`review` → rich result для приложения недоступен;
- бренд в схеме (`Football. LIVE`) не совпадает с брендом в title и тексте (`Live Score`).

## 4. Новые проблемы, появившиеся после чистки

### 4.1. P0 — `llms.txt` и `llms-full.txt` теперь ведут на 38 мёртвых страниц

Файлы не обновлялись (в плане это вынесено в «deferred»). Проверка всех URL, которые они анонсируют:

| Источник | Ссылок (вхождений) | 200 | 404 | 307 |
|----------|--------------------|-----|-----|-----|
| `llms.txt` | 15 | 7 | **7** | 1 |
| `llms-full.txt` | 46 | 7 | **38** | 1 |
| **Всего вхождений** | **61** | 14 | **45** | 2 |
| **Уникальных URL** | **47** | 8 | **38** | 1 |

То есть **81% уникальных URL из llms-файлов — 404** (38 из 47). Для «машиночитаемого описания сайта» это хуже, чем отсутствие файла: агент получает инструкции перейти на удалённые разделы `/pricing`, `/faq`, `/guide/*`, `/privacy`, `/terms`.

**Фикс:** переписать оба файла под 6 URL (они уже перечислены в `llms.txt`, но вперемешку с удалёнными). Это ~15 минут работы и единственный оставшийся артефакт, который прямо врёт о структуре сайта.

### 4.2. P1 — 404-страницы отдают битый HTML и не локализованы

Все 42 удалённых URL возвращают **правильный статус 404** и `noindex` — это хорошо. Но тело документа:

```
status=404
body: <meta charSet="utf-8"/><meta name="viewport" …><meta name="robots" content="noindex"/>
      <title>404: This page could not be found.</title>
      <div style="…"><h1>404</h1><h2>This page could not be found.</h2></div>
      …</body></html>
```

- **нет `<!DOCTYPE html>`, нет открывающих `<html>`, `<head>`, `<body>`** — документ начинается с `<meta>`;
- нет `<html lang>` (проверено: `lang=-`), то есть страница не определяется как язык-специфичная;
- текст всегда английский, даже на `/ru/...`, `/ar/...`;
- нет шапки, футера и ссылки на главную — пользователь попадает в тупик;
- `src/app/[locale]/not-found.tsx` (с локализованным заголовком и ссылкой `Home`) **не рендерится никогда**: для неизвестного пути Next берёт глобальный 404, а для невалидной локали ошибка возникает в layout, чей собственный boundary не может её отрисовать. Файл фактически мёртвый.

Причина — `src/app/layout.tsx` возвращает `children` без `<html>`/`<body>`; нормальный документ собирается только внутри `[locale]/layout.tsx`, а 404 идёт вне него.

**Фикс:** добавить `src/app/not-found.tsx`, который сам отдаёт `<html lang="en"><body>…</body></html>` с шапкой/ссылкой на `/en`. Тогда 42 мёртвых URL будут выглядеть как нормальная страница, а не как ошибка сервера.

### 4.3. P1 — юридических страниц больше нет вообще

`privacy` и `terms` удалены из роутов и контента. Раньше это были заглушки `TODO` (плохо для SEO), теперь — отсутствие политики конфиденциальности и условий (плохо для доверия, для Telegram Mini App, для сторов и для рекламных платформ). Плюс с точки зрения E-E-A-T: нет ни privacy, ни terms, ни «о проекте», ни контактов — только Telegram-бот.

**Рекомендация:** вернуть 2 страницы на локаль (или один `/legal`), но уже с реальным текстом: оператор, контакты, какие данные обрабатываются (Telegram, Stars), сроки, применимое право. Индексировать их не обязательно.

### 4.4. Замечание — `pnpm build` на старом `.next` падает после удаления маршрутов

Первый билд после `19d4c43` упал:

```
PageNotFoundError: Cannot find module for page: /api/official-channels
Error: Failed to collect page data for /api/official-channels
```

Причина — артефакты предыдущей сборки (48 маршрутов) в `.next`. После `Remove-Item .next -Recurse -Force` сборка проходит (19 статических страниц), повторная сборка поверх свежего `.next` тоже проходит. На Vercel/CI с чистым checkout проблемы не будет; локально после таких удалений нужен чистый `.next`.

## 6. Что значит «одна страница на локаль» для SEO

**Плюсы:** нет тонких/дублирующихся страниц, весь вес и все ссылки идут на один URL, нет каннибализации, проще поддерживать 6 страниц вместо 48.

**Минусы:** одна страница может уверенно ранжироваться по 1–3 интентам, не больше. Сейчас `/{locale}` пытается закрыть сразу: «футбольные счета в Telegram», «уведомления о матчах», «бот для группы», «бот для канала», «Chat Premium / 49 Stars», «официальные каналы лиг», «FAQ». Конкуренция идёт за них в разных SERP-выдачах, и один title (`Live Score — football scores and match alerts in Telegram`) покрывает только первый.

**Как компенсировать без возврата к 48 страницам:**

1. **Секции с анкорами** уже есть (`#features`, `#how-it-works`, `#pricing`, `#official-channels`, `#faq`) — они должны быть видимы в HTML (см. 3.2), тогда один URL может собирать длинный хвост по «how to…»-запросам.
2. **Вернуть 2–3 страницы, а не 7** — только там, где интент не помещается на главную и есть 300–400 уникальных слов: `/{locale}/pricing` (49 Stars, Free vs Premium) и `/{locale}/guide` (подключение группы/канала + скриншоты). Остальное (`privacy`, `terms`) — как legal, без ставки на SEO.
3. **FAQ — на главную, но видимым текстом** и с `FAQPage`-схемой: 8 вопросов уже написаны, схема уже написана (`faqPageJsonLd`), нужно только вернуть импорт и рендер панелей.
4. **Не индексировать 5 «второстепенных» локалей раньше времени** — или наоборот, дать им отдельные title/description под локальные запросы (сейчас все 6 — перевод одного и того же оффера).
