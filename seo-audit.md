## 3. Что сломалось в этом раунде

### 3.1. P0 — секция «How it works» полностью выпала из HTML

В `HomeLanding.tsx:64-70` секция обёрнута в `<Suspense fallback={null}>`, а «How it works» — клиентский компонент, который читает query-параметр через `useSearchParams` (`src/hooks/useQueryTab.ts:14`). После перехода на ISR (`src/app/[locale]/page.tsx:28`, `revalidate = 300`) страница стала статической, и Next срезал этот участок в клиентский рендер: в HTML остаётся `fallback: null`.

Проверено:

```
raw 'How it works' в HTML:        false
id="how-it-works" в HTML:         false
текст в RSC-payload (__next_f):   есть ("fallback":null, children: [HowItWorksTabs …])
h2 на странице:                   6 (было 7 — пропал заголовок секции)
```

Следствия:

1. **213 слов** копирайта (заголовок, описание, 3 панели с шагами для личного чата, групп и каналов) отсутствуют в HTML — это ровно те инструкции «как подключить группу/канал», под которые ищут.
2. **Битый анкор**: все локали в меню ссылаются на `/{locale}?how=groups#how-it-works` (и `how=channels`), но элемента с `id="how-it-works"` в документе нет → переход по пункту меню не скроллит к секции.
3. Для краулеров без JS и для LLM-агентов страницы секции просто нет.
4. В round 2 (при `force-dynamic`) секция частично попадала в HTML (~52 слова: заголовок + первая панель) — это регресс, а не «так и было».

**Фикс (любой из двух):**

- **A. Убрать `useSearchParams` из серверного пути**: передавать `how` пропсом, а выбор таба восстанавливать в `useEffect` после монтирования (читать `window.location.search`). Тогда компонент снова рендерится на сервере, а deep-link `?how=groups` продолжает работать после гидрации.
- **B. Сделать секцию серверным компонентом**: рендерить все три панели списками `<ol>` (с `hidden` только для неактивных), а переключение табов делать клиентской обёрткой. Это ещё и даёт краулеру все 213 слов.

Критерий готовности: `id="how-it-works"` присутствует в HTML, в нём есть три `<ol>` с шагами, `h2` «How it works» в дереве заголовков.

### 3.2. P1 — 404-страницы по-прежнему битые

42 исторических URL (и любой опечатанный адрес) отдают 404 и `noindex`, но документ невалиден:

```
/en/pricing → 404
  <!DOCTYPE html>: нет
  <html …, <head>, <body>: нет открывающих тегов — документ начинается с <meta charSet="utf-8"/>
  <title>: "404: This page could not be found." (английский на всех локалях)
  навигации, шапки, футера, ссылки на главную: нет
```

Причина — `src/app/layout.tsx` возвращает `children` без `<html>`/`<body>`; настоящий документ собирается только в `[locale]/layout.tsx`, а 404 рендерится вне него. `[locale]/not-found.tsx` при этом не используется: для неизвестного пути Next берёт глобальный 404, а для невалидной локали ошибка возникает в layout, чей собственный boundary её не отрисует.

Дополнительно `/de` отдаёт `<html id="__next_error__">` без `lang` и с заголовком из layout — то есть 404 в проекте фактически два разных, и оба не локализованы.

**Фикс:** добавить `src/app/not-found.tsx`, который сам отдаёт полный документ (`<html lang="en"><body>…`) с шапкой и ссылкой на `/en`; локализованную версию оставить как fallback для `notFound()` внутри `[locale]`.

### 3.3. P1 — OG-картинки: размеры не совпадают с метаданными

Все 5 файлов существуют и отдаются (200, `image/jpeg`), но реальный размер — **1024×576**, а в разметке заявлено **1200×630** (`seo-metadata.ts:71-73`, `layout.tsx:36-40`).

| Файл | Факт | Заявлено |
|------|------|----------|
| `og-en.jpg` | 1024×576 | 1200×630 |
| `og-es/fr/pt/ru.jpg` | 1024×576 | 1200×630 |

Для Telegram и X это не критично (превью отрисуется), но: соотношение сторон 16:9 против заявленного 1.905:1 → возможна обрезка; часть площадок доверяет заявленным размерам и рендерит слот 1200×630, куда картинка апскейлится с потерей резкости.

**Фикс:** либо переэкспортировать в 1200×630, либо поставить в метаданные честные `width: 1024, height: 576`.

### 3.4. P1 — 2 из 8 ответов `FAQPage` не совпадают с видимым текстом

`plainFaqAnswer()` (`seo-jsonld.ts:95-105`) разворачивает markdown-ссылки в `label (url)`, поэтому в схеме появляются голые URL, которых нет на странице:

```
схема:    "Open the bot (https://t.me/LiveScoreAppBot), send /group, and pick a group…"
страница: "Open the bot, send /group, and pick a group…"
```

Затронуты оба вопроса про подключение — «How do I connect a group?» и «How do I connect a channel?» (во всех 6 локалях). Остальные 6 ответов совпадают. Формально Google требует, чтобы ответ в `FAQPage` присутствовал на странице; URL в скобках — отклонение, которое может стоить rich result.

**Фикс:** в `plainFaqAnswer` заменять `[label](url)` только на `label` (без URL) — либо оставить URL, но добавить такой же текст в видимый ответ.
